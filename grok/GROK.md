Читай этот файл целиком перед первой правкой. Он не про стиль кода, а про то,

Твоя половина работы — **точная**: исполнение решённых задач, тесты (включая
проверку мутацией), согласованность документации с кодом, разбор чужих диффов,

## 1. Закон проекта

Эти правила дороже любого отдельного улучшения. Нарушение — повод откатить работу
целиком, каким бы полезным ни был результат.

1. **Замер до правки.** Число, названное ДО эксперимента, — единственное основание
   менять поведение поиска, извлечения или ранжирования. «Стало лучше» без числа
   здесь не аргумент: отбор стоп-слов в FTS выглядел очевидным улучшением и уронил
   recall 0.583 → 0.458.
2. **Ревью-гейт неприкосновенен.** Ничто не становится каноническим знанием без
   решения человека. Массовые операции физически не имеют права создавать знания.
3. **Изоляция арендаторов.** Каждая строка принадлежит аккаунту; поиск, граф,
   диалоги, файлы и инструменты ограничены им. Законное чтение поверх — только
   надзорными инструментами с явным правом и записью в аудит на **целевой** аккаунт.
4. **Провенанс обязателен.** Путь ответ → `[K#]` → Knowledge Object → Raw Object
   прослеживается всегда. Ответ без источника — дефект.
5. **Модель не создаёт фактов.** Извлечение сущностей детерминированное; LLM —
   советчик, её предложения сами в граф не попадают.
6. **Максимум функционала — в Telegram.** Новая возможность сначала должна работать
   в чате; самый дешёвый путь — инструмент агента. Ответы в чат идут **без**
   Markdown-разметки: мессенджер показывает `**` и `|` сырыми знаками.
7. **Данные владельца не покидают машину и не попадают в разговор** — только числа,
   вердикты, хеши.

## 3. Отрицательные результаты — не повторять

- Накопление графового вклада по числу общих сущностей (noisy-or) — ноль эффекта.
- Отбор стоп-слов в FTS — recall 0.583 → 0.458.
- Префикс `explicit_*` как право писать в граф — раздавал полномочия по имени метода.
- **Передать `kg` в `memory_search`** («граф же есть, почему он не используется»):
  замерено на золотом наборе живого архива — recall@10 **0.35 → 0.15**, MRR 0.153 → 0.063,
  чистый счёт −4 кейса из 20, ранг ухудшен в 7 случаях против 1 улучшенного. Контроль на
  копии без 4349 узлов-людей: −5, то есть канал вредил и до прохода правилом ФИО, сильнее.
  Цена сверх того +556 мс (107 → 662). Оговорка: мерено на вопросах «найди документ»;
  на реляционных вопросах канал не мерён, эталонов такого типа нет.
- **Править `personal_cue` / порог 0.35 из‑за «вопрос про человека → болтовня»** без
  переизмерения поиска: после `graph_expansion=False` формы из переписки уже дают
  hits и `personal_knowledge|mixed` (11/12), болтовня 8/8 остаётся
  `general_conversation`. Ночной 4/5 general_conversation был hits=0 от поиска, не
  дефект классификатора (G10 / #39).
- Обнаружение противоречий по полосе косинуса 0.78–0.92 — ловит обратное.
- Нормировка скора пассажей на длину документа — перекоса нет.
- `min_score` в переранжировщике — доказуемый no-op.
- Показ «лучшего из отсеянных» — отвечает 1 раз из 8.
- Смена стека на Qdrant / Neo4j / Celery / React — см. `docs/STATE_2026-07-31.md`.
- Типы сущностей Risk и Metric (V2) — правилами 4% и 3% точности, моделью 40% и 46%;
  поправка «рядом число с единицей» дала 92% на 13 находках и 50% на 48. Порог 75%
  при выборке >=30 объявлен до замера и не взят. См. комментарий у `EntityType`.

## 4. Как проверяется работа

```
.venv/bin/ruff check .
.venv/bin/ruff format --check jericho tests tools
.venv/bin/mypy jericho
.venv/bin/bandit -r jericho -q          # 0 HIGH
node --check friday/admin_ui/static/app.js
.venv/bin/python -m pytest -q
```

**Мутация обязательна для нового теста**: сломай защищаемый код и убедись, что тест
падает. Зелёный тест на сломанном коде здесь ловили многократно.

Полезные приёмы, проверенные в этом проекте:
- ассерт по подстроке — не пин (`"idx_x" in plan` пройдёт на любом индексе с этим
  префиксом); сравнивай точные имена;
- инвентарный тест, пропускающий часть поверхности, скрывает дефект именно в ней;
- тест «настройка живая» по регулярке имени ничего не гарантирует — нужна матрица
  «точка входа × значение».

**Сторожа поверхности** (`test_bridge_surface.py`, `test_route_inventory.py`,
`test_storage_surface.py`, `test_docs_do_not_outlive_the_code.py`) падают на любом
расширении API, команд, методов хранилища. Обнови константу и напиши рядом причину.

## 5. Рабочий порядок

- **Работа заканчивается пушем в `main`.** Это правило владельца: незапушенная
  работа для команды не существует. Значит гейт (§4) прогоняется ДО пуша, а не
  после — ревью postfactum здесь нет, и сломанный `main` увидят все.
- Перед пушем: `git pull --rebase` (двое пишут в одну ветку), затем полный гейт,
  затем `git push`. Историю не переписываем, `--force` не используем никогда.
- Если гейт красный — не пушим и пишем причину в `PROPOSALS.md`. Незелёный `main`
  дороже любой задержки.
- Коммит по-русски: что изменилось, **почему** и каким числом подтверждено; тон —
  как в `git log`.
- Правишь поведение поиска, извлечения, прав или схемы — сначала предложение в
  `grok/PROPOSALS.md`.
- Комментарий в коде пишется только тогда, когда объясняет ограничение, которое из
  кода не видно (замер, отвергнутый вариант, грабля). Не пересказывай соседнюю
  строку.

## 6. Окружение

- Модели поднимаются на твоей машине; адреса и ключи — в `.env.local`, в репозиторий
  они не попадают и в предложениях не цитируются.
- У тебя **свой** `FRIDAY_HOME`. Живой экземпляр владельца и каталог `~/.jericho` —
  не трогать.
- Долгие прогоны против моделей согласовывать: карта одна на три службы.
- Нужны данные — подними синтетический корпус; в живую базу тестовые данные не сеять.

## 8. Твоя папка

`grok/` — твоя. В ней:

- `GROK.md` — этот файл;
- `PROPOSALS.md` — предложения;
- всё остальное, что ты пишешь **для себя**: черновики, разовые скрипты замеров,
  заметки по разбору. Держи здесь, а не в корне репозитория.

Код, который идёт в продукт, живёт в `friday/` и `tests/` по общим правилам —
своя папка не отменяет ни гейта, ни ревью, ни сторожей поверхности. Разовый скрипт
замера, наоборот, лучше оставить у себя: он документирует, чем получено число.

Вторая папка — `sol/` — принадлежит второму помощнику. Не правь её файлы:
если нужно что-то сказать ему, пиши в своём `PROPOSALS.md`, владелец сведёт.
