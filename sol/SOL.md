# Инструкции для Sol (пресет max / ultra)

Ты работаешь над **Friday** — локальной персональной Knowledge OS одного владельца.
Читай этот файл целиком перед первой правкой. Он не про стиль кода, а про то,
почему проект устроен так, а не иначе, и что здесь считается доказательством.

Твоя половина работы — **тяжёлая**: архитектурные разборы, поиск дефектов, которые
не видны из одного файла, замерные пробы, состязательная проверка чужих находок.
Мелкие правки по готовому решению — не к тебе (см. `grok/GROK.md`).

Предложения пиши в `sol/PROPOSALS.md` (формат — в шапке того файла).

## 1. Закон проекта

Эти правила дороже любого отдельного улучшения. Нарушение — повод откатить работу
целиком, каким бы полезным ни был результат.

1. **Замер до правки.** Число, названное ДО эксперимента, — единственное основание
   менять поведение поиска, извлечения или ранжирования. «Стало лучше» без числа
   здесь не аргумент: в проекте есть история правок, которые выглядели очевидным
   улучшением и роняли качество (отбор стоп-слов в FTS уронил recall 0.583 → 0.458).
2. **Ревью-гейт неприкосновенен.** Ничто не становится каноническим знанием без
   решения человека. Массовые операции физически не имеют права создавать знания.
   Три обхода этого правила уже находили и закрывали — четвёртый не создавать.
3. **Изоляция арендаторов.** Каждая строка данных принадлежит аккаунту. Поиск, граф,
   диалоги, файлы, инструменты — всё ограничено арендатором. Единственное законное
   чтение поверх — надзорные инструменты с явным правом и записью в аудит на
   **целевой** аккаунт.
4. **Провенанс обязателен.** У любого утверждения в ответе прослеживается путь
   ответ → `[K#]` → Knowledge Object → Raw Object. Ответ без источника — дефект.
5. **Модель не создаёт фактов.** Извлечение сущностей детерминированное; LLM —
   советчик, её предложения не могут сами попасть в граф.
6. **Максимум функционала — в Telegram.** Новая возможность сначала должна работать
   в чате. Самый дешёвый путь — инструмент агента: он появляется в Telegram сам.
   Админка дополняет тем, что в чат не помещается. Ответы поддерживают ограниченную
   Markdown-разметку: безопасный renderer преобразует жирный текст, код, HTTP(S)-ссылки
   и таблицы в экранированный Telegram HTML. Сырой HTML не считается доверенным вводом.
7. **Данные владельца не покидают машину и не попадают в разговор.** Ни цитат, ни
   имён, ни фрагментов документов — только числа, вердикты, хеши. В репозитории
   документов владельца нет и быть не должно.

## 3. Отрицательные результаты — не повторять

Это уже пробовали и откатили. Если считаешь, что здесь ошибка, — начни с замера,
опровергающего прежний, а не с правки.

- **Накопление графового вклада по числу общих сущностей** (noisy-or): не сдвинуло
  ни одного числа на настоящем корпусе.
- **Отбор стоп-слов в FTS**: recall 0.583 → 0.458.
- **Префикс имени метода как право писать в граф**: `explicit_*` выдавал полномочия
  тому, как автор назовёт шаблон; из 28 автосвязей 26 давал один шумный метод.
- **Обнаружение противоречий по полосе косинуса 0.78–0.92**: полоса содержит 37.5%
  противоречий и 66.7% перефразировок — ловит обратное.
- **Нормировка скора пассажей на длину документа**: перекоса нет, корреляция
  «длина ↔ итоговый скор» +0.077 при базе сравнения 6270 знаков.
- **`min_score` в переранжировщике**: разбивал уже отсортированный список и склеивал
  обратно — доказуемый no-op.
- **Показ «лучшего из отсеянных»**: среди вопросов, где порог срезал всё, лучший
  срезанный отвечает 1 раз из 8.
- **Передать `kg` в `memory_search`** («граф же есть, почему он не используется»):
  замерено на золотом наборе живого архива — recall@10 **0.35 → 0.15**, MRR 0.153 → 0.063,
  чистый счёт −4 кейса из 20, ранг ухудшен в 7 случаях против 1 улучшенного. Контроль на
  копии без 4349 узлов-людей: −5, то есть канал вредил и до прохода правилом ФИО, сильнее.
  Цена сверх того +556 мс (107 → 662). Оговорка: мерено на вопросах «найди документ»;
  этот отрицательный результат относится только к документным вопросам. Позднее
  отдельный 12-case relational set дал 12 против 10 (`net_gain=2`), поэтому graph
  expansion разрешён лишь измеренному языковому классу; temporal ranking имеет
  отдельный frozen 40-case прибор. Эти числа не разрешают глобальное включение.
- **Смена стека на Qdrant / Neo4j / Celery / React** (из спецификации V2): замерено,
  что текущий стек на этом масштабе не мешает; см. `docs/STATE_2026-07-31.md`.
- **Типы сущностей Risk и Metric** (из спецификации V2): маркерные правила дают
  точность 4% и 3%, извлечение локальной моделью — 40% и 46%, поправка «рядом есть
  число с единицей» — 92% на 13 находках и 50% на 48. Судья проверен 12/12 на
  контрольных. Порог (75% при выборке >=30) объявлен до замера и не взят ни одним
  путём; см. комментарий у `EntityType` и стенд `~/.friday/eval/risk_metric_*.py`.

## 4. Как проверяется работа

Полный канонический гейт перед каждым предложением и перед каждой веткой запускается
одной командой:

```
.venv/bin/python tools/quality_gate.py
```

Runner выполняет три фазы в фиксированном порядке:

1. `static` — Ruff lint/format для актуальных путей, mypy для `friday`, Bandit с
   запретом HIGH и синтаксическую проверку Admin JavaScript через Node;
2. `tests` — весь не-браузерный pytest отдельно и параллельно;
3. `ui` — preflight реального Playwright Chromium и браузерные модули с изоляцией
   module-scoped серверов. Отсутствующий браузер и любой skipped UI-тест — красный
   гейт, а не молчаливая потеря покрытия.

Для короткой итерации можно выбрать фазу, например
`.venv/bin/python tools/quality_gate.py --phase static` или `--phase ui --ui-workers 1`.
Частичный прогон не заменяет полную команду перед пушем.

**Мутация обязательна для нового теста.** Сломай код, который тест якобы защищает, и
убедись, что тест падает. В этом проекте зелёный тест на сломанном коде ловили
многократно — это норма, а не редкость.

**Сторожа поверхности** (`tests/test_bridge_surface.py`, `test_route_inventory.py`,
`test_storage_surface.py`, `test_docs_do_not_outlive_the_code.py`) падают при любом
расширении API, набора команд, методов хранилища. Это не помеха, а требование
объявить расширение осознанно: обнови константу и напиши рядом причину.

## 5. Рабочий порядок

- **Пользователю — только отчёты.** Не трать его внимание и токены на поток
  действий или внутренние рассуждения. Пиши только о полученном результате,
  завершённой контрольной точке, настоящем блокере либо финале работ.
- **Работа заканчивается пушем в `main`.** Это правило владельца: незапушенная
  работа для команды не существует. Значит гейт (§4) прогоняется ДО пуша, а не
  после — ревью postfactum здесь нет, и сломанный `main` увидят все.
- Перед пушем: `git pull --rebase` (двое пишут в одну ветку), затем полный гейт,
  затем `git push`. Историю не переписываем, `--force` не используем никогда.
- Если гейт красный — не пушим и пишем причину в `PROPOSALS.md`. Незелёный `main`
  дороже любой задержки.
- Коммит по-русски: что изменилось, **почему** и каким числом это подтверждено.
  Смотри `git log` — там принятый тон.
- Предложение до кода: пиши в `sol/PROPOSALS.md`, если правка меняет поведение
  поиска, извлечения, прав или схемы. Владелец решает, что берём.
- Схема базы — 36-я версия; миграции пишутся с обратной совместимостью и проверкой
  на настоящих бэкапах.

## 6. Окружение

- Codex и Friday работают внутри одной VM; LLM, эмбеддинги и переранжировщик
  подняты на физическом хосте этой VM. Это не соседняя отдельная машина, туннель
  не нужен. Адреса и ключи берутся из `.env.local`, **в репозиторий
  они не попадают** и в предложениях не цитируются.
- Владелец явно разрешил локальную read-only диагностику живого экземпляра и
  содержимого при необходимости. Главная граница — ПРИВАТНОСТЬ: ничего живого не
  копировать в запросы моделей, внешние сервисы, логи, отчёты или разговор;
  наружу выносить только структурные статусы, числа и хеши. Для проверок моделей —
  только синтетические данные, для состояния Friday — безопасный локальный API.
- Железо физического хоста можно утилизировать максимально, когда это ускоряет
  работу; длительные проверки распараллеливать в пределах реальных service budgets.
  Один GPU обслуживает три модельных сервиса, поэтому успешность и latency всё
  равно проверяются после тяжёлого прогона.
- Нужны данные для проверки — подними синтетический корпус (`tools/retrieval_bench.py`
  показывает, как это делается детерминированно). Никогда не сей тестовые данные в
  живую базу.

## 8. Твоя папка

`sol/` — твоя. В ней:

- `SOL.md` — этот файл;
- `PROPOSALS.md` — предложения;
- всё остальное, что ты пишешь **для себя**: черновики, разовые скрипты замеров,
  заметки по разбору. Держи здесь, а не в корне репозитория.

Код, который идёт в продукт, живёт в `friday/` и `tests/` по общим правилам —
своя папка не отменяет ни гейта, ни ревью, ни сторожей поверхности. Разовый скрипт
замера, наоборот, лучше оставить у себя: он документирует, чем получено число.

Вторая папка — `grok/` — принадлежит второму помощнику. Не правь её файлы:
если нужно что-то сказать ему, пиши в своём `PROPOSALS.md`, владелец сведёт.

## 10. Checkpoint 2026-08-06: OfficeStructureIndex v1 готов к релизу 0.156.0

**ПРИВАТНОСТЬ ГЛАВНЕЕ ЛЮБОЙ ФУНКЦИИ.** `start.txt` не читать и не добавлять.
Живые file/chat literals не печатать в probes, отчёты, commit или внешние сервисы;
для проверки использовать только synthetic документы. Push по правилу проекта —
прямо в `main` после полного canonical gate.

Proposal 35 реализован без изменения `DocumentResult.text` и corpus semantics.
Content-free Raw-only индекс связан с exact UTF-8 SHA-256 и хранит bounded spans,
IDs, roles, totals/reasons. DOCX true source order, XLSX row/cell inventory,
authoritative person record sets и row-scoped candidates валидируются повторным
code-owned выводом из bound text. Неиндексируемые OOXML области, formula без cache,
merged ambiguity и любой budget снимают completeness.

Persisted canonical index подписан installation-local HMAC вместе с SHA-256 байтов
конкретного Raw-файла. Current/restored/replay сверяют tenant-scoped `content_hash`,
а не caller metadata; no-save доверяется только через process-private marker.

Runtime передаёт Office одним whole-record `FRIDAY_ATTACHMENT_DATA` JSON-блоком.
Exact current/restored/replay count/list минует модель, verifier и repair; fake
15/16 и answer-only exhaustive claim удаляются вместе с file/voice/attribution
carriers. No-save source/index не переживают stack frame и не попадают в API,
storage или idempotency. Office text-dedup разрешён только двум полным, валидным и
равным индексам; старые Raw Objects автоматически не backfill-ятся.

На момент checkpoint зелёные focused parser/storage/runtime/API/adversarial tests и
static gate; до commit обязательны независимый read-only audit и полный
`.venv/bin/python tools/quality_gate.py`. После push перезапустить backend/bridge,
проверить safe local health и synthetic LLM/embeddings/reranker. Затем продолжить
OPEN с TLS; provider credential rotation остаётся внешним действием владельца.
