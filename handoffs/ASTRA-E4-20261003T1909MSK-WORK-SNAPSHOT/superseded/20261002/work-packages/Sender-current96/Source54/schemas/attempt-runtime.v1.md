# attempt-runtime.v1

Encoding: canonical ASCII JSON, sort_keys=True, compact separators, allow_nan=False and one LF. Duplicate/unknown/missing keys and noncanonical round trips fail. External expected SHA256 is mandatory for authority documents; local/staged/self manifests never supply trust. Lowercase 64-hex digests, exact bools versus ints, bounded paths/counts/depth/sizes. Every nested record is exact-key checked by the named source parser. Source constants define the closed executable field inventory; source-review-index binds their symbols and tests.

Parser: broker_runtime.RuntimeJournal. Exact keys: schema,attempt_id,consumed_sha256,identity_sha256,generation,phase,previous_journal_sha256,journal_sha256,outcome,evidence_sha256,records. records is the exact flattened predecessor history; each predecessor excludes records but its digest is verified with the corresponding earlier prefix restored. Generation, identity, predecessor hash and exact forward phase transitions are checked for every record. Retained successors follow consumed->snapshot_verifying->snapshot_held->namespace_sealing->namespace_sealed->live_admitting->lock_held->running->collecting->publishing->terminal_pass|terminal_fail. No phase rollback. Recovery of any incomplete consumed prefix finalises FAIL only and does not invoke custody/live/exec.

terminal_pass is provisional. A separate terminal-commit.v1.json binds schema,attempt_id,consumed_sha256,runtime_sha256,evidence_sha256,outcome; terminal-failure.v1.json is a permanent veto binding schema,attempt_id,consumed_sha256,outcome,reason. Any existing veto, including malformed metadata or bytes, forbids PASS. Ambiguous recovery preserves the journal and evidence and creates failure rather than rewriting terminal history. Complete commit/publication acceptance must be bound to the same consumed/runtime/evidence identity and absence of the veto; failed/unknown publication never grants PASS or a retry. Additional source limitations are recorded in result.json and source-review-index.json.

broker_runtime.validate_terminal_commit is a read-only acceptance API requiring the accepted supervisor's external runtime digest, exact commit/evidence/consumed binding, stable no-follow commit metadata and no veto before and after reading. It does not infer trust from a terminal directory and does not resume an interrupted attempt. Interrupted invocation must recover to failure before any acceptance is considered.

run_once now holds the live fence/signal guard through prepare_finalize, terminal commit and read-only acceptance. Only final close releases the fence. Any close/late-signal ambiguity permanently vetoes a provisional commit. A synchronous SupervisorResult binds attempt, consumed, runtime, evidence and commit hashes and complete finalization; a foreign/unfinished object refuses. Its new attempt-supervisor-result.v1 wire projection is carried by the new friday.supervisor-transport.v1 envelope, which also binds run-v1, authority/grant/runtime-index/package/interpreter pins. Serialized bytes are NOT self-authenticating: an external reader must independently authenticate the invocation/channel, observe complete EOF and exact integer successful final status. Directory reads, a callback assertion or output emitted before process completion never supplies that authority. The bootstrap fixture main is wired to this read-only consumer; production refuses before loading because protected startup/external anchor proof is absent.
